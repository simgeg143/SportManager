CHANGE 4 — Global overflow prevention + long method signature breakpoints
DATE: Mar 14, 2026
REASON: Inline \texttt{} calls with long method signatures (e.g.
        updateStandings(result: MatchResult), sport.applyInjuries(match))
        were overflowing the right margin in body text paragraphs and lists.
        \texttt does not hyphenate, so there were no natural break points.
WHAT CHANGED:
  - Added \setlength{\emergencystretch}{3em} to the preamble (global fallback
    that gives LaTeX up to 3em of extra space-stretch to avoid overfull lines).
  - Split long method signatures into two adjacent \texttt{} pieces with
    \allowbreak between them, e.g.:
        \texttt{updateStandings}\allowbreak\texttt{(result:\,MatchResult)}
    Break point is placed at the opening parenthesis (function name / params).
  - Used \, (thin space) instead of ": " inside parameter lists to reduce width.
  LINES FIXED:
    - §4 item list: selectSport, selectManagedTeam, advanceWeek, startMatch
    - §4.b League item list: getMatchesOfWeek, updateStandings
    - §4.7 Playing a match: sport.applyInjuries
    - §6 Sport interface: createLeague, createTeam, createPlayer, createMatch,
      calculatePoints, trainTeam, applyInjuries
RESULT: No more overflow from method signatures in body text.

CHANGE 22 — FootballMatch.buildResult(): removed dead loop, added bench scan
DATE: Mar 14, 2026
FILE: src/main/java/com/sportmanager/football/FootballMatch.java
BUG:  The injury-collection loop over segment events (lines 96-101) was
      completely empty — it parsed nothing. Additionally, only starting-XI
      players were scanned for injuries; bench players were ignored.
FIX:
  - Removed the empty event-parsing loop entirely.

    covering both getStartingLineup() and getSubstitutes().
  - Bench injuries are now tagged "Injured in warm-up" to distinguish them.

--------------------------------------------------------------------------------
CHANGE 23 — FootballMatch.teamAttack/teamDefense: removed unsafe cast
DATE: Mar 14, 2026
FILE: src/main/java/com/sportmanager/football/FootballMatch.java
BUG:  Both teamAttack() and teamDefense() used an unconditional
      (FootballPlayer) p cast — any non-FootballPlayer in the lineup would
      throw ClassCastException.
FIX:  Replaced cast with a pattern-matching instanceof check:
        p instanceof FootballPlayer fp ? fp.getAttackScore() : p.getSkillLevel() * 0.8
      Non-FootballPlayer instances fall back to a skill-based estimate.

--------------------------------------------------------------------------------
CHANGE 24 — FootballTeam.generateDefaultLineup(): assigns currentLineup
DATE: Mar 14, 2026
FILE: src/main/java/com/sportmanager/football/FootballTeam.java
BUG:  generateDefaultLineup() filled startingLineup and substitutes directly
      but never created or assigned a Lineup object to currentLineup. As a
      result, Team.hasValidLineup() always returned false (null check failed)
      even with a full 11-man XI.
FIX:  Added at the end of generateDefaultLineup():
        this.currentLineup = new Lineup(startingLineup, substitutes);
      Added missing import for com.sportmanager.core.Lineup.

--------------------------------------------------------------------------------
CHANGE 25 — FootballLeague.generateFixtures(): handles odd team count
DATE: Mar 14, 2026
FILE: src/main/java/com/sportmanager/football/FootballLeague.java
BUG:  The circle-method algorithm assumes an even number of teams. With an odd
      count, integer division (n/2) would produce inconsistent round sizes and
      the rotation logic would be incorrect.
FIX:  Added a BYE-slot (null) to the rotation list when n is odd:
        if (n % 2 != 0) rotation.add(null);
      During round generation, any fixture where either team is null is simply
      skipped — that team has a bye that round. The fix is transparent: callers
      see correct fixture lists with no dummy matches.
